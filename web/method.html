What happens in your browser

Every inference step stays on the device. The server provides static files but never receives the submitted title or abstract.

  1. 01

    Read several views of the text

    The title, complete title-plus-abstract, and tokenizer-aware specialist passages are read separately. Long abstracts use overlapping chunks instead of silently losing the ending.

  2. 02

    Create semantic vectors

    A quantized MiniLM transformer uses attention layers and mean pooling to create normalized 384-dimensional representations. A compact learned query transformation adapts them to EGU retrieval.

  3. 03

    Compare every scientific session

    The query views are compared with precomputed title and description vectors for all 786 typical EGU26 sessions. Special events such as medals, short courses, town halls, and administrative sessions are excluded.

  4. 04

    Combine five relevance signals

    The scorer combines joint text similarity, title-to-title, title-to-description, passage-to-title, and passage-to-description matches using weights learned on past assignments.

  5. 05

    Adapt the number of suggestions

    A validation-calibrated score-gap rule returns a short set for focused abstracts and a broader set for ambiguous ones. You can still reveal the next ten sessions through the complete ranking.

Ranking, not classification

The score is comparative

Each cosine term measures the angle between two normalized vectors. The learned non-negative weights determine how much each scientific view contributes.

cos(q,s)= q·s ‖q‖2⁢‖s‖2 score=∑i wi⁢similarityi

The value is useful for ordering sessions, but it is not the probability that a session is “correct.” Close leading scores indicate genuine ambiguity.

02

Historical construction

From programme pages to training pairs

The preparation pipeline is deliberately separate from the public site. It can be computationally expensive; the exported matcher remains compact.

A

Cache the programmes

Session pages for 2020–2026 were collected gently and cached locally, with parsers for the different historical page layouts.

B

Recover abstracts

Crossref records with Copernicus EGU DOI prefixes provide titles and abstracts. Original source-file and line locations remain traceable.

C

Join accepted assignments

Abstract identifiers from programme pages link each abstract to its recorded session. Multiple valid assignments are preserved instead of forcing one label.

D

Prevent leakage

Session representations contain only official code, division, title, and description—never abstracts already accepted into that session.

Evaluation through time

Past years keep their roles

Training and model choice never see the future. Sparse 2020–2021 public assignments are retained only as auxiliary catalogues.

Static deployment

Expensive preparation.
Lightweight use.

The selected model is exported to quantized ONNX. Session vectors are prepared once, stored compactly as float16, and verified by checksum when loaded.

No API endpoint receives the abstract. The only network requests fetch immutable application, model, and catalogue assets.

Use with scientific judgment

What the matcher cannot decide

Historical assignments are imperfect labels: some abstracts could fit several sessions, and some may have been submitted strategically or incorrectly.

Similarity does not account for conveners’ unpublished preferences, late programme changes, invitation status, or author eligibility.

Always read the official description and submission rules. The tool supports navigation; it does not replace the programme or make a submission decision.
